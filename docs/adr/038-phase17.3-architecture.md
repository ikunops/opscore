## 0. Abstract

ADR-037 (Phase 17.3 Scope) was **ACCEPTED in Round 80 (verdict A)** — the direction is sound and the
Scope is CLOSED. This ADR resolves the architecture questions GPT required before any code is written
(`docs/adr/037-phase17.3-scope.md` §7/§8). It carries the eight scope MUST laws (R17-0…R17-8) and the
one Round-80 tightening, **MUST-17.3-A**, into concrete design.

> **MUST-17.3-A (R80 tightening).** The `correlationID` replay guard is **strict-reject (`409
> Conflict`)**. There is **NO** configurable allow mode in Phase 17.3. A new mutation request whose
> `correlationID` already has a terminal `outcome` is rejected. Rationale: `correlationID` is the
> mutation identity boundary; permitting a second mutation under an already-terminal id would fork one
> causal chain into many, degrading audit causal integrity — the opposite of reconciliation's goal.
> (The scope's earlier "configurable strict-reject vs flag-and-allow" R17-S2 is **withdrawn** for
> Phase 17.3.)

The architecture introduces **three additive capabilities** on the existing `:8082` management surface:
1. a read-only **reconciliation scanner** (`Scan` — orphaned-INTENT detection + report; **no** automatic
   forward-synthesis in Phase 17.3),
2. a management-scoped **audit read surface** (`GET /management/v1/audit`, `GET /management/v1/reconciliation`),
3. a **`correlationID` replay guard** at the mutation entry point (MUST-17.3-A).

All three are **observer/validator/reporter** layers over the existing INTENT→CAS→OUTCOME protocol
(R17-2). **No mutation semantics change. No Control Plane. No `external/v1` change.**

## 2. Freeze boundaries (carried from ADR-037, with MUST-17.3-A)

- **R17-0** `external/v1` read-only Public Contract UNCHANGED; audit viewer only on `:8082`.
- **R17-1** No Control Plane / orchestration / new process; reconciliation is in-process, on-demand (or
  startup best-effort once), **never** a scheduler/worker/controller.
- **R17-2** INTENT→CAS→OUTCOME protocol NOT modified; reconciliation is an additive observer layer.
- **R17-3** Fail-safe, forward-only reconciliation; committed mutations NEVER auto-rolled-back.
- **R17-4** `AuditStore` interface change ADDITIVE only (`ListByCorrelation`); no breaking signature,
  no schema migration (v4 columns already present).
- **R17-5** Frozen packages unmodified; derive from existing fields. Any audit read-model shaping lives
  in `internal/management` (or `internal/management/auditview`), **not** in frozen packages.
- **R17-6** Management audit read surface is **read-only** (`GET` only); no `POST/PATCH/DELETE` on audit.
- **R17-7** AuthN/AuthZ on the read surface (same token, fail-closed) — write and read share ONE gate.
- **R17-8** No new dependency; reuse `AuditStore`, `encoding/json`, `governancepolicy.Repository.Get`.
- **MUST-17.3-A** `correlationID` replay guard is **strict-reject `409`**, no configurable allow.
- **MUST-17.3-B** (R81 tightening). `Scan` is **strictly read-only** — it NEVER calls `audit.Append`; the
  `GET /management/v1/reconciliation` route invokes `Scan` **only**. Reconciliation **never synthesizes a
  success/failure outcome without provable attribution** to this `correlationID`. An orphaned intent the
  current schema cannot tie to a committed mutation is reported as `unresolved` (or `no_match`), **never
  fabricated into success** — audit trustworthiness > resolved-count. Inference
  `observedRevision >= intentRevision ⇒ committed` is **explicitly forbidden** as proof.

## 3. Architecture

### 3.1 `AuditStore` read model (R17-4/R17-5) — additive only

The existing interface (`internal/storage/storage.go`):

```go
type AuditStore interface {
    Append(e AuditEvent) (AuditEvent, error)
    List(limit int) ([]AuditEvent, error)
    ListByOperation(op string, limit int) ([]AuditEvent, error)
}
```

**Add exactly one method** (additive; existing methods untouched):

```go
// ListByCorrelation returns audit events sharing a correlationID, most-recent
// first. It is a QUERY VIEW ONLY — it provides no consistency guarantee against
// a concurrent mutation; the replay guard (§3.4) treats its result as a
// point-in-time hint, not a proof.
ListByCorrelation(correlationID string, limit int) ([]AuditEvent, error)
```

**SQLite implementation** (`internal/storage/sqlite/stores.go`):

```sql
SELECT id, timestamp, actor, operation, action, target, result, detail,
       capability_hash, execution_id, snapshot_schema_version, revision, correlation_id
FROM audit_events
WHERE correlation_id = ?
ORDER BY id DESC
LIMIT ?
```

- **No schema migration.** The `correlation_id` column already exists (v4, ADR-035/036).
- **Optional non-breaking index** (perf only, safe to add):
  `CREATE INDEX IF NOT EXISTS idx_audit_corr ON audit_events(correlation_id);`
  `IF NOT EXISTS` ⇒ idempotent, no migration version bump.
- The in-memory `AuditStore` (test double) gains the same method; it is **not** a frozen package.

### 3.2 Reconciliation scanner (R17-1/R17-2/R17-3/R17-6) — read-only by construction

A new package-local type `internal/management/reconcile` (or a `reconciler` field on `Server`):

```go
type Reconciler struct {
    audit storage.AuditStore
    repo  governancepolicy.Repository   // READ-ONLY use (Get)
}

// ReportEntry is the stable, parseable reconciliation result (GPT R80 §4 schema, extended R81).
type ReportEntry struct {
    CorrelationID    string `json:"correlation_id"`
    PolicyID         string `json:"policy_id"`
    IntentRevision   int    `json:"intent_revision"`
    ObservedRevision int    `json:"observed_revision"`
    Status           string `json:"status"`     // "closed" | "unresolved" | "no_match"
    Resolution       string `json:"resolution"` // human-readable note
}
```

**Two methods, strictly separated (R17-6).** `Scan` is pure read; `ReconcileForward` writes — and
Phase 17.3 calls **only `Scan`.**

**`Scan(ctx)` — pure read / report generation (R17-6 read-only):**

1. `events := audit.List(scanCap)` — bounded full scan (operator-triggered; single-node audit store is
   small). Page if needed.
2. Collect `intent` events (result == `intent`). For each intent `e`:
   - `tail := audit.ListByCorrelation(e.CorrelationID, 4)` — all events sharing this id.
   - **If `tail` contains a terminal `outcome`** (`result ∈ {success, failure}`) → **not orphaned**;
     mark `status="closed"`, `resolution="terminal outcome already recorded"`. Skip (nothing to do).
   - Else → **orphaned** (an `intent` with no paired outcome). Resolve by **evidence, not inference**:
     - `rec, ok, _ := repo.Get(e.PolicyID)` → `observed := rec.Revision` if `ok`, else `revisionUnknown`.
     - **If `!ok`** (policy target no longer exists) → `status="no_match"`,
       `resolution="target policy gone — cannot attribute; no synthesis"`. No write.
     - **If `ok`** → the policy exists at `observed`. **But the current schema records no field that
       links a specific committed mutation to this `correlationID`** — `repo.Get` yields only the
       *current* revision, not *who* produced it. `observed >= e.Revision` therefore proves only that
       *some* mutation happened, **never** that *this intent* committed it. Per **MUST-17.3-B**, an
       unattributable intent is **never** synthesized into success. → `status="unresolved"`,
       `resolution="orphaned intent; revision movement observed but not attributable to this intent —
       no auto-synthesis (R17-3 fail-safe, R81)"`. No write.

**`ReconcileForward(ctx, correlationID)` — writes, defined but NOT invoked in Phase 17.3 (R17-6):**

- Its contract would synthesize an outcome **only** when a *provable* link exists between the intent and
  a committed mutation (e.g. a future audit schema that records, per committed revision, the
  `correlationID` that produced it). **That linkage does not exist in the Phase 17.3 schema.**
- Consequently, in Phase 17.3 `ReconcileForward` is a **no-op that reports** — it returns
  `status="unresolved"` and appends nothing. It is documented here as the seam a future Major (with the
  attribution field) would wire; it is intentionally **not** reachable from any `GET` route or startup
  path in this phase.
- If ever invoked, its only write would be a distinguishing `audit.Append` of a success outcome
  (`detail` carries `reconciled:true`) — never a repository mutation. That write path is covered by the
  same `TestNoCASBypass` / `TestReconciliationDoesNotMutate` AST guard as the rest of the surface.

**Invariants (carried + R81 tightenings):**
- `Scan` calls `repo.Get` (read) **only**; it **never** calls `Save`/`CompareAndSave`/
  `CompareAndTransition`/`Activate`/`Deactivate`/`Archive`, and it **never calls `audit.Append`**. A
  `Scan` produces `[]ReportEntry` and leaves the audit store byte-for-byte unchanged (R17-6).
- The `GET /management/v1/reconciliation` route calls `Scan` **only** (§3.3); it performs no persistence
  side-effect.
- The synthesized outcome (in `ReconcileForward`, future) is distinguishable (`detail` marker
  `reconciled:true`) so operators can see it was produced by reconciliation, not the live mutation path.

### 3.3 Management audit read surface (R17-0/R17-6/R17-7) — read-only, `:8082`

Two new routes registered on the **management mux** (same `Handler()`), inside the existing `guard`:

```go
mux.HandleFunc("GET "+RoutePrefix+"audit", s.handleListAudit)
mux.HandleFunc("GET "+RoutePrefix+"reconciliation", s.handleReconcile)
```

- `GET /management/v1/audit?policy={id}&result={intent|success|failure}&limit=N`
  — returns the management-owned audit events (`audit.List` / filtered in memory by `policyID` +
  `result`). Returns `[]AuditEvent`-derived view (never the external/v1 governance *summary*).
- `GET /management/v1/reconciliation`
  — runs `reconciler.Scan(ctx)` (pure read) and returns `[]ReportEntry` as stable JSON. It is a **report**,
  not a **repair** (GPT R80 §4): `Scan` performs **no** persistence side-effect (R17-6 / MUST-17.3-B) and
  never mutates policy or audit state.

Both inherit the **same `guard`** (AuthN+AuthZ wrap the whole mux, per `server.go` `Handler()`), so an
unauthenticated `GET` is rejected fail-closed (R17-7) — there is **no** "write protected, audit viewer
public" leak. The `RoutePatterns()` set grows from 5 → **7**; the existing
`TestRoutePatternsAreManagementScoped` assertion is updated to `7` (this is the management package's own
test, not a frozen invariant).

**Mechanical isolation (R17-0):** the harness `assertNoManagementRoutes(mux)` build assertion
(ADR-036 §3.6) already proves no `/management/v1/...` route is mounted on the `external/v1` mux. The two
new `GET` routes are added to the management mux only, so they remain covered by that assertion. No
change to `external/v1` is possible without breaking the build.

### 3.4 `correlationID` replay guard (MUST-17.3-A) — entry point, strict-reject

**Client-supplied key.** Today `serveMutation` generates `corr` server-side (after AuthN/AuthZ). For
replay protection the **caller supplies** a key via header `Idempotency-Key` (RFC 7231-style). If absent,
the server generates one (current behavior) — replay protection applies only when the caller opts in by
sending a key.

**Check placement.** At the very top of `serveMutation`, **before STEP 1 (INTENT)**:

```go
supplied := r.Header.Get("Idempotency-Key")
if supplied != "" {
    if tail, _ := s.audit.ListByCorrelation(supplied, 1); hasTerminalOutcome(tail) {
        writeError(w, newAPIError(http.StatusConflict, codeReplayConflict,
            "correlation id %q already has a terminal outcome; replay rejected", supplied))
        return
    }
}
corr := chooseCorrelationID(supplied, s.newCorrelationID)  // use supplied if given
```

- `hasTerminalOutcome` = any event in `tail` with `result ∈ {success, failure}`.
- On hit → **`409 Conflict`** (MUST-17.3-A). **No** flag-and-allow, **no** configuration knob.
- The chosen `corr` (supplied or generated) flows into the INTENT/OUTCOME records as today.

**Race handling (GPT R80 §4).** `ListByCorrelation` is a point-in-time query (R17-4 note), so a
near-simultaneous duplicate could both pass the guard before either appends its outcome. This is
**acceptable** for Phase 17.3 because:
- The repository `CompareAndSave`/`CompareAndTransition` is still the authoritative atomic gate; a true
  concurrent double-apply is refused by `ErrRevisionConflict` at CAS time (the existing conflict path),
  recording a `failure` outcome for the loser.
- The replay guard's job is to stop *obvious* replays (same id, already-terminal), not to provide
  linearizable mutual exclusion — that would require a Control Plane (forbidden, R17-1). MUST-17.3-A is
  satisfied: any request arriving *after* a terminal outcome exists is rejected; the guard is strict,
  just not lock-free-perfect. This trade-off is documented in the ADR and accepted.

### 3.5 Startup best-effort scan (R17-1) — no controller

- At server start (inside `assembleManagement` / `Serve` of the harness, in-process), run
  `reconciler.Scan(ctx)` **once, non-blocking, best-effort**: errors are **logged, not fatal**; a failed
  scan must not prevent `:8082` from binding or serving mutations. `Scan` is pure read (R17-6), so the
  startup pass only logs the report — it never writes.
- There is **no** recurring scheduler, worker, queue, leader election, or background operator (R17-1).
  Reconciliation runs (a) once at startup, (b) on-demand via `GET /management/v1/reconciliation`. Both
  are synchronous request/response, never a detached process.
- The reconciler holds no long-lived lock; it reads `AuditStore` + `Repository.Get` under the existing
  per-store mutexes.

### 3.6 Mechanical isolation guarantees (R17-0/R17-5/R17-6)

- **No execution bridge (read-only `Scan`).** `Scan` and the audit read handlers call `repo.Get` (read)
  and `audit.{List,ListByCorrelation}` only. `Scan` MUST NOT call `audit.Append`. The future
  `ReconcileForward` write seam (only) may call `audit.Append`, and is covered by the same guard. The
  policy repository stays strictly read (`repo.Get`); nothing calls `Save`/`Activate`/`Deactivate`/
  `Archive`/`CompareAndSave`/`CompareAndTransition`. **Extend the existing `TestNoCASBypass` AST guard**
  (management package) to cover `reconcile.go` and the two new read handlers — adding `audit.Append` to
  the forbidden-call set for the `Scan`/read-surface source (or add `TestReconciliationDoesNotMutate`
  asserting no write-method call appears there). Either way, a regression that makes reconciliation mutate
  policy or audit fails the build.
- **Read-only surface.** Add `TestAuditReadSurfaceIsReadOnly` (or extend `guards_test.go`) asserting the
  two new routes are registered with `GET` method only and that no `POST/PATCH/DELETE` audit route is
  registered.
- **Frozen-package zero-diff.** `git diff` of frozen packages (`platform`, `governance`,
  `plugin/{runtime,isolation}`, `controlplane/hostregistry`, `external`, `governancepolicy`,
  `platformview`) MUST be empty. The only storage change is the additive `ListByCorrelation` + optional
  non-breaking index in `internal/storage/sqlite` (non-frozen).

## 4. Data-flow (reconciliation, read-only observer)

```
              ┌─────────────────────────────────────────────┐
              │  management/v1 mux  (guarded: AuthN+AuthZ)   │
              └─────────────────────────────────────────────┘
                 │ GET /audit        GET /reconciliation        POST/PUT/... (unchanged)
                 │                       │                          │
        ┌────────┴──────┐       ┌────────┴─────────┐     ┌─────────┴──────────┐
        │ handleListAudit│       │ reconciler.Scan  │     │ serveMutation      │
        │  audit.List    │       │  (READ-ONLY)     │     │  (existing pipeline)│
        └───────┬────────┘       └────────┬─────────┘     └─────────┬──────────┘
                │                         │                          │
                ▼                         ▼                          ▼
        ┌──────────────┐        ┌─────────────────┐      ┌──────────────────┐
        │ AuditStore    │        │ AuditStore       │      │ AuditStore        │
        │ .List         │        │ .List/.ListByCorr│      │ .Append (intent/  │
        └──────────────┘        │ + repo.Get(READ) │      │  outcome)          │
                                │ → returns report  │      └──────────────────┘
                                │   (APPENDS NOTHING)│
                                └─────────────────┘
        Scan is READ-ONLY: it reads audit + repo.Get and returns []ReportEntry.
        It never calls audit.Append. ReconcileForward (future, not wired in 17.3)
        is the only write seam, and it is unreachable from any GET route.
```

## 5. Error contract (carries R17-6/R17-7)

| Scenario | Status | Body |
|---|---|---|
| Unauthenticated `GET /audit` / `/reconciliation` | `401` | `{error: "unauthenticated"}` |
| Authenticated but lacking `policy:manage` | `403` | `{error: "forbidden"}` |
| Replay guard hit (terminal outcome for `Idempotency-Key`) | `409` | `{error: "correlation id already has a terminal outcome; replay rejected"}` |
| `GET /audit` ok | `200` | `[{...audit events...}]` |
| `GET /reconciliation` ok | `200` | `[{ReconciliationReport entries}]` |

The replay-guard `409` and the existing CAS `409` (`ErrRevisionConflict`) are distinct causes but share
the code; the `code` field disambiguates (`codeReplayConflict` vs `codeConflict`).

## 6. Out of scope (carried from ADR-037)

- Modifying `external/v1`; any Control Plane / HA / orchestration / scheduler / worker.

- Any change to the read-only probe (`/healthz` `/readyz` `/versionz`) or the Runtime Contract.

## 11. Deferred / open questions (non-blocking, recorded at R83 close)

These do **not** block the close of Phase 17.3. They are recorded so a future phase cannot
silently absorb them without a fresh Scope ADR.

- **OQ-17.3-1 — `ReconcileForward` activation requires a new Scope ADR.** The seam is currently a
  no-op observer. Activating it introduces `audit evidence → repair action → state transition`,
  which is a **control capability**, not observation. It MUST NOT be enabled as an "implementation
  detail" of any later phase.
- **OQ-17.3-2 — Audit query scale.** `GET /management/v1/audit` currently does `audit.List(limit)`
  plus in-memory filtering, which is correct for the Phase 17.3 boundary. If the audit table grows,
  the fix is a storage-backed `AuditQuery` abstraction (predicate pushdown into SQLite), **not**
  more logic in the management handler. Performance evolution, not a present defect.
- **OQ-17.3-3 — `internal/plugin/runtime` gofmt drift (8 files).** Per R79-C, frozen-package
  zero-diff outranks formatting. Left untouched deliberately; requires explicit owner authorization.

## 2. 设计（四项，各自最小改动）

### 2.1 P2-2：`decodeJSON` 的缺席体 = 显式错误

`r.Body == nil ⇒ return errors.New("request body required")`。**调用点审计**：10 处全部是
**体必需**端点（login/register/execute/batch/hosts×n/kill/quota×2/submit），无一依赖
「缺席体 ⇒ 零值继续」；空（非 nil）体走既有 `io.EOF` 路径 ⇒ 400（P1-6 同族纪律）。
⇒ 缺席体在任何调用点都变成**明确的 400**，不再有「零值→401」的混淆路径。

### 2.2 P2-3：run 的操作结果不再冒充服务器故障

`handleRun` 的操作结果**一律 200**（`success`/`cancelled` 字段承载业务结果）；
5xx 语义收窄为真正的服务器故障。理由：操作失败（如目标机没有该服务）是**已完成的请求
报告了否定结果**，把它映射为 500 会让代理/告警/重试机制把业务否定误读为服务器故障。
**声明的行为变更**（§4）；gate 拒绝仍用其自有状态码；`plan` 失败路径（404/500）不动
（计划失败不是操作结果）。

### 2.3 P2-4：注释语言约定成文（不追溯重写）

写入 `docs/operations.md` §3：**代码注释/错误消息英文**（可 grep、日志单一语言），
**ADR/运维文档/UI 文案中文**；既有注释**不追溯重写**（避免噪声 diff 淹没语义变更）。

### 2.4 P2-5：demo 假主机的禁用声明硬化

`demo.go` 的 `InsecureIgnoreHostKey: true` 字段处加显式警示：该字段只对
`127.0.0.1` 上进程内假主机成立（`net.Listen("tcp", "127.0.0.1:0")`，`demo.go:68`），
**绝不用于真机**；真机连接必须验证主机键。

## 4. 声明的行为变更（穷举）

1. **P2-2**：任何处理器收到 `Body == nil` 的请求 ⇒ 400（此前：视处理器而定，或零值继续、
   或 401）。生产路径（`net/http` 服务器）不会产生 nil Body；此变更消除的是**非标准传输/
   测试/未来调用方**下的混淆失败模式。
2. **P2-3**：`POST /api/operations/{name}/run` 的操作失败 ⇒ 200（体不变：`success:false`）；
   `ui.html` 的状态展示随之变化（该面板只展示 `status/ok/body`，不做分支——已核对）；
   既有集成测试的 500 断言更新为新契约（作为见证）。
3. **P2-4/P2-5**：仅文档与注释，零行为变更。

## 5. 自对抗（预判评审会打的点，先自答）

| 预判质疑 | 自答 |
|---|---|
| **Q1「P2-3 改 500→200 会不会破坏既有消费者？」** | 已穷举消费者：`ui.html` 只展示（§4.2 已核对）；集成测试是唯一断言 500 的位置，作为见证更新；CLI/`opscore-cli` 不经此端点。且新语义**更**可监控：真正的 5xx 不再被业务否定淹没。 |
| **Q2「P2-2 为什么不把空体也算 400？」** | 空体（EOF）在**部分**端点是有意义的缺席——但那些端点（plan/execute/batch params）走 `decodeParams`（空体 ⇒ 空 map）而非本函数；`decodeJSON` 的调用点全部体必需 ⇒ EOF ⇒ 400 已是正确行为，只需把 nil 体并入同一纪律。 |
| **Q3「P2-4 不成文会怎样——为什么值得一个 Phase 条目？」** | 它是**唯一**能防止未来评审再次提出「注释语言混用」的机制（把它从「观察」变成「约定」）；成本一行，收益是纪律可引用。 |
| **Q4「这四项配一个 Phase 吗？」** | 它们是 R244/质量基线登记在册的 **P2 打磨项**（owner 指定队列最后一项）；本 ADR 不声称新判据——修的是呈现/语义/纪律四笔小债，每条都有判别或成文出口（§3/§2.4）。 |
